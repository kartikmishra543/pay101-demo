4. Account and Credential Security You are responsible for protecting merchant login details and ensuring only authorised personnel access the dashboard and Services.

The API documentation describes a merchant login that returns a Bearer JWT and requires X-Authorization-Key and X-Module-Secret headers for the relevant PayIn and PayOut API calls.

You must protect these credentials, AES Key and AES IV, and any Transaction PIN (TPIN). Never expose them in client-side code, public repositories, URLs, or unsecured logs. Use secure server-side storage, least-privilege access, and prompt rotation or revocation if credentials may have been compromised.

You must promptly notify support@pay101.io of suspected unauthorised access.

5. API Integration and IP Whitelisting You must implement the Services according to the current Pay101 API documentation and maintain secure systems.

The API documentation states that API access is restricted to whitelisted IP addresses and instructs merchants to provide their server outbound IP addresses to Pay101 before going live. Merchants must notify Pay101 if those addresses change and should include relevant staging and production servers.

The documentation specifies AES-256-CBC encryption for PayIn payloads, while PayOut payloads are sent as JSON without that payload encryption. Merchants must follow the exact current technical specification and contact Pay101 if any instructions are unclear.

Pay101 may update technical requirements with reasonable notice where practicable, subject to the Merchant Agreement.

6. PayIn, Callbacks and Payment Verification Merchants must provide accurate order and customer details and a valid HTTPS callback URL as required by the API documentation. A callback is a notification and should not, by itself, be treated as final proof that a payment succeeded.

The API documentation instructs merchants to call the payment verification endpoint after receiving a callback and to credit a customer only after an independently confirmed SUCCESS response.

Merchants are responsible for implementing this verification flow, handling duplicate or delayed notifications safely, and maintaining their own order records.
